OPPORTUNITYTRACK ADMIN PANEL - EASY ONE-TIME SETUP
==================================================

After this one-time setup, daily updates are simple:
Admin Panel -> Add New -> fill the form -> Save Content.
No HTML/code editing is needed for normal updates.

1) UPLOAD THIS WEBSITE TO YOUR EXISTING GITHUB REPOSITORY
----------------------------------------------------------
Upload the CONTENTS of this folder to the repository root.
index.html must be directly in the root, not inside another folder.
Commit and Push. Your existing Cloudflare Pages project will deploy it.

2) CREATE ONE CLOUDFLARE D1 DATABASE
------------------------------------
Cloudflare Dashboard -> Storage & Databases -> D1 -> Create database
Name it:
  opportunitytrack-db

You do NOT need to paste SQL manually. The website creates its required tables
automatically the first time the Admin setup page connects to the database.
The file migrations/0001_schema.sql is included only as a backup/reference.

3) CONNECT THE DATABASE TO YOUR CLOUDFLARE PAGES SITE
------------------------------------------------------
Cloudflare Dashboard -> Workers & Pages -> your OpportunityTrack Pages project
-> Settings -> Bindings -> Add -> D1 database

Binding / variable name MUST be exactly:
  DB

Select:
  opportunitytrack-db

Save it, then redeploy the latest deployment once.

4) CREATE YOUR SUPER ADMIN
--------------------------
Open:
  https://YOUR-DOMAIN/admin-setup

Enter:
- Super Admin username
- Email
- Strong password
- Recovery key

IMPORTANT: save the recovery key somewhere safe outside the website.
The setup page automatically locks after the first Super Admin is created.

5) NORMAL DAILY USE
-------------------
Open the public website and click the floating "Admin Panel" button at the
bottom-right.

Normal Admin login shows only:
- Username
- Password
- Forgot password
- Super Admin Login button underneath

From the dashboard you can add/edit/delete:
- Scholarships
- Admissions
- Internships
- Fellowships
- Jobs
- Schemes
- Updates

Editable fields:
- Title
- Category
- Organization / University
- Country and City
- Funding / Type
- Degree / Applicant Level
- Deadline
- Published Date
- Featured On/Off
- Published / Draft status
- Short Description
- Eligibility
- Full Details
- Application Link
- Official Source Link
- Tags

The PUBLIC DESIGN IS FIXED by the website template. Editing text or fields in the
Admin Panel cannot change the card spacing, fonts, colors or detail-page layout.

6) ADMIN AND SUPER ADMIN
------------------------
Normal Admin:
- Add, edit, publish, draft and delete opportunity content.

Super Admin:
- Everything a normal Admin can do.
- Create normal Admin accounts.
- Enable/disable Admin accounts.
- See normal Admin password-reset requests.
- Set a new temporary password for a normal Admin.

Forgot password:
- Normal Admin: the request appears in the Super Admin dashboard.
- Super Admin: use /admin-recover and the recovery key saved during setup.

7) HOW NEW CONTENT APPEARS ON THE SITE
--------------------------------------
Choose Scholarship -> it appears automatically on Scholarships.
Choose Admission -> Admissions.
Choose Internship -> Internships.
Choose Fellowship -> Fellowships.
Choose Job -> Jobs.
Choose Scheme -> Schemes.
Choose Update -> Updates.

If Featured is ON, it can also appear in the Featured section on the homepage.
All recently published items can appear in the Latest section and site search.
Each published item automatically gets a detail URL like:
  /opportunities/example-opportunity-name

8) ADSENSE / CONTENT QUALITY
----------------------------
The existing long About, FAQ, Contact, Privacy, Guides and category guidance remain
on the website. New Admin content is shown above those pages in a consistent format.
Do not copy full descriptions from another website. Write a clear original summary
and add the official application/source links so users can verify the current facts.

9) SEO
------
The live sitemap is generated automatically at:
  /sitemap.xml

It includes published opportunity detail pages.
robots.txt is also generated from the live domain.

The sitemap and robots.txt use the live domain automatically. Static page canonicals
are relative, so the build does not need a hard-coded production domain.
